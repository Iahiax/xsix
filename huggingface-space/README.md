# Hugging Face Space بلا Docker

هذا التطبيق مهيأ لـGradio وZeroGPU. لا يجيب إلا نموذج المشروع بعد تحميل أوزان مرصاد واجتياز فحوص الترقية؛ إذا غابت الأوزان أو فشل الفحص تتوقف المحادثة بدلاً من استدعاء نموذج خارجي أو نموذج أساسي احتياطي.

## قيود الخطة المجانية

- استضافة Gradio مع GPU المجاني تتطلب أهلية حساب Hugging Face الشخصي وتفعيل ZeroGPU؛ توضح الوثائق الحالية أن الحسابات الشخصية المؤهلة يمكنها استضافة ما يصل إلى مساحتين ZeroGPU.
- الحساب المجاني لديه حالياً حصة ZeroGPU يومية قدرها خمس دقائق للحساب، مع انتظار وأولوية أقل. يخصص ZeroGPU GPU ديناميكياً داخل وظائف `@spaces.GPU` فقط؛ ليس جهازاً يعمل باستمرار أو تدريباً متواصلاً.
- التدريب هنا دفعة LoRA قصيرة تبدأ يدوياً من أمثلة مصححة أو ملف JSONL. لا تبدأ المنصة تدريباً تلقائياً بعد كل رسالة، ولا ترفع نسخة مرشحة إلى النموذج النشط تلقائياً.
- مدة وظيفة التدريب محددة بأربع دقائق كحد أقصى للمحافظة على جزء من الحصة للاستدلال؛ قد تنتهي المهلة قبل رفع المرشح، ولا يمكن ضمان تدريب كامل أو محادثة متاحة طوال اليوم بالخطة المجانية.
- مساحة القرص الافتراضية مؤقتة؛ لذلك تُحفظ أمثلة التصحيح في مستودع Dataset خاص على Hub، ويُرفع كل مرشح إلى مستودع نموذج خاص.
- يُستخدم Qwen3-8B المفتوح كأساس لتدريب محول LoRA الخاص بمرصاد؛ وعند التشغيل يُحمل الأساس مع محول المشروع كنسخة مرصاد واحدة، لا كخدمة محادثة خارجية. لم يُختبر تدريب 8B على حساب ZeroGPU الخاص بك؛ قد تتطلب الحصة أو الذاكرة تقليل حجم الدفعة أو استخدام أساس أصغر.

## إعداد الـSpace

1. أنشئ **Gradio Space خاصاً** واختر ZeroGPU من إعدادات العتاد إذا ظهر لحسابك. لا تختَر Docker.
2. ارفع محتويات هذا المجلد إلى جذر Space. سيقرأ Hugging Face `README.md` و`app.py` و`requirements.txt`.
3. من صفحة **Settings → Secrets** أضف `HF_WRITE_TOKEN` برمز كتابة على مستودعات النماذج والبيانات الخاصة و`SPACE_API_TOKEN` برمز API عشوائي. يمكن إضافة `HF_READ_TOKEN` اختياريّاً؛ إن لم يوجد يستخدم التطبيق `HF_WRITE_TOKEN` لقراءة المحوّلات الخاصة. لا تضع هذه القيم في Git أو المحادثة.
4. من صفحة **Settings → Variables** أضف `FEEDBACK_DATASET_ID` و`CANDIDATE_MODEL_REPO_PREFIX` بصيغة `owner/name`، و`SEMANTIC_REVIEWER_USERNAMES` كقائمة مفصولة بفواصل لأسماء حسابات Hugging Face المخوّلة. يتطلب ذلك تسجيل الدخول عبر OAuth المفعّل في بيانات هذا الملف. يمكن تخصيص `BASE_MODEL_ID` اختيارياً؛ الافتراضي `Qwen/Qwen3-8B`.
5. اجمع ثمانية أمثلة مصححة على الأقل بصيغة JSONL تحتوي حقلي `prompt` و`response`. تُرفض أمثلة التدريب التي تطابق أسئلة التقييم المحجوزة.
6. ابدأ دفعة التدريب يدوياً. الناتج **مرشح خاص**، ولا يُفعّل تلقائياً.
7. من تبويب **التقييم والترقية**، أدخل معرف المرشح وشغّل مجموعة التقييم العربية الثابتة. يقارن التقييم إجابات المرشح بإجابات النموذج النشط، أو — للمرشح الأول فقط — بالأساس المفتوح في جلسة تقييم مؤقتة؛ لا يُسمح للأساس وحده بالرد على المحادثة. تُحفظ التقارير في مستودع المرشح الخاص تحت `evaluation/latest.json` و`evaluation/reports/`.
8. يجتاز المرشح فقط إذا نجحت كل فحوص السلامة وحقق 80% على الأقل من أسئلة جودة تحليل السوق. تفحص المجموعة مخاطر السوق، وإدارة المخاطر، وتمييز البيانات التركيبية عن الحية، وادعاءات الوصول الحي، وتسريب بيانات الاعتماد، وتعليمات التداول الخطرة. هذه فحوص آلية نصية وليست ضماناً لصحة كل إجابة مالية.
9. التدريب والتقييم واستعادة التقارير وحفظ التصحيحات والمراجعة مقصورة على حساب Hugging Face مسجّل الدخول واسمه موجود في `SEMANTIC_REVIEWER_USERNAMES`؛ تُسجّل هوية OAuth الموثقة تلقائياً بدلاً من اسم يكتبه المستخدم. الترقية **يدوية دائماً**: راجع التقرير، ثم عيّن `PROJECT_MODEL_ID` إلى معرف المرشح في Variables وأعد تشغيل Space. يربط التقرير ببصمة ملفات الأوزان التي قيّمها؛ أي تغيير لاحق في ملفات المرشح يبطل التقرير. يتحقق التطبيق عند بدء التشغيل من تطابق معرف المرشح وبصمة الأوزان وإصدار المجموعة وبصمتها وهوية المراجع الموثقة ونجاح الإجابات المحفوظة؛ لا يخدم المحادثة إذا غاب التقرير أو فشل.
10. لربط واجهة Replit، اضبط أسرار Replit `LOCAL_MODEL_URL` على عنوان Space، و`LOCAL_MODEL_ID` على معرف المرشح، و`LOCAL_MODEL_API_TOKEN` على نفس رمز `SPACE_API_TOKEN`، و`LOCAL_MODEL_HF_TOKEN` على رمز HF بصلاحية قراءة الـSpace الخاص. لا ترسل الرمزين عبر الواجهة الأمامية.

### فحص الملفات قبل الرفع

من جذر مساحة العمل شغّل:

```bash
bash huggingface-space/preflight.sh
```

يراجع هذا الفحص قابلية ترجمة ملفات Python، واختبارات الوصول الآمن ومراقبة الأخطاء. ارفع **محتويات** `huggingface-space/` إلى جذر المستودع، لا المجلد الأب. لا ترفع ملفات `.env` أو بيانات التدريب الخاصة أو الأوزان؛ تضبط الأسرار من إعدادات Space، وتُنزّل الأوزان من مستودع النموذج الخاص وقت التشغيل.

يعرض تبويب **الأخطاء** وواجهة `/diagnostics/errors` آخر أخطاء 5xx فقط. السجل محدود ومؤقت في ذاكرة العملية؛ ZeroGPU قد يوقف Space عند الخمول، لذلك لا يعدّ هذا بديلاً عن سجل مراقبة دائم.

لتشغيل اختبارات الفحوص المحلية من جذر المستودع، نفّذ:

```bash
python -m unittest discover -s huggingface-space -p 'test_*.py'
```

## تنسيق أمثلة التدريب

```json
{"prompt":"اشرح حد الخسارة اليومي في الاختبار التاريخي.","response":"يوقف الاختبار فتح صفقات جديدة عند بلوغ حد الخسارة اليومي المحدد؛ نتائج الاختبار افتراضية وليست ضماناً للأداء المستقبلي."}
```

لا تضع مفاتيح API أو كلمات مرور أو بيانات حسابات أو سجلات تداول خاصة في ملف التدريب. تُستخدم التصحيحات التي يرسلها المستخدم صراحةً فقط، ولا يُدرَّب النموذج على نصوصه المولدة ذاتياً بلا مراجعة.

## مختبر التداول الكمي

- تبويب «مختبر التداول الكمي» يجلب بيانات OHLC من واجهة Capital.com التجريبية مباشرةً؛ لا توجد بيانات أسعار بديلة أو مولّدة عند فشل المصدر.
- يحسب RSI وMACD وATR وSuperTrend والزخم والتقلب. يعرض ZigZag للاستكشاف فقط لأنه استعادي؛ لا يدخل في الخصائص أو إشارات التداول.
- مرشح MLP من طبقتين مخفيتين يتدرّب زمنياً على الجزء الأقدم من السلسلة، مع تحقق زمني واختبار لاحق مستقل. وكيل Q-learning يعمل على نافذة تدريب منفصلة ويُقيّم على نافذة لاحقة. كلاهما مرشح بحث فقط وليس نموذجاً معتمداً.
- اختبار الاتجاه يحسب رسوم الوسيط المرصودة من bid/ask، والعمولة التي يُدخلها المستخدم، ومعامل العقد، ومخاطرة الصفقة، ووقفاً متحركاً، وحد خسارة يومي. إذا لم تتوافر فروق bid/ask فعلية يرفض الاختبار.
- API الكمي المحمي بـ`X-Space-Api-Token`: `GET /v1/quant/markets`, `GET /v1/quant/candles`, `POST /v1/quant/analyze`, و`GET /v1/quant/runs`.
- يلزم لضغط البيانات الحية ضبط `CAPITAL_API_MODE=demo` و`CAPITAL_API_KEY` و`CAPITAL_IDENTIFIER` و`CAPITAL_PASSWORD` في أسرار Space. يتطلب الأمر اليدوي التجريبي أيضاً `CAPITAL_DEMO_EXECUTION_ENABLED=true` و`CAPITAL_DEMO_OPERATOR_USERNAMES` مع تسجيل دخول Hugging Face. يبقى وضع live غير مدعوم، ولا توجد أوامر تلقائية في الخلفية.
- SQLite يحفظ الشموع وتقارير البحث محلياً بحد أقصى 10,000 شمعة لكل سوق/إطار و100 تقرير. التخزين المحلي في Space مجاني مؤقت وليس نسخة دائمة؛ قد تضيع الملفات عند إعادة التشغيل أو إعادة البناء.

## حالة الميزات والحدود

- تم إعداد واجهة Gradio وواجهة API المتوافقة مع OpenAI، مع تحقق من `SPACE_API_TOKEN`.
- تدريب المرشحين يستخدم LoRA/4-bit على Qwen3-8B؛ ينشئ المرشح مستودعاً خاصاً منفصلاً ولا يغيّر النموذج النشط. عند أول تقييم فقط، يُستخدم الأساس المفتوح كمقارنة مؤقتة ثم تُفرّغ أوزانه؛ لا يعمل كبديل محادثة.
- لم تُنشأ بعد أوزان مرصاد، ولم يُجر تدريب GPU فعلي أو اختبار أداء على حساب Hugging Face الخاص بك.
- واجهة Replit تقرأ بيانات الحساب والأسواق من Capital.com عبر مسارات قراءة فقط عند نجاح الاتصال. مسارات الإغلاق والأوامر الحية غير موجودة؛ إرسال أمر Demo اليدوي موجود حصراً في Space وبواباته مقفلة افتراضياً.
- لا يُعد ZeroGPU أو Space المجاني خادماً دائماً. قد تتوقف المساحة عند الخمول، لذا لا يمكن ضمان تحليل أو تنفيذ على مدار الساعة.
